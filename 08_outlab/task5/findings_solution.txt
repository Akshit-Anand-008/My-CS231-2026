== A4. Diagnosis ==
hotspot 1: cause = branch misprediction because the six tests read random bits of x (confirmed by experiment, see A3)
hotspot 2: cause = dependency chain because each of the 7 loads needs the value of the one before, at a random address
hotspot 3: cause = branch misprediction because the chase-or-not test is random (1 in 8), plus the calls it makes

== B3. One level deeper ==
## cold_column_probe: the inner loop is over row; history is 4096 rows x 2048 ints = 32 MB, row-major, so each step
## jumps 8 KB. At 128 columns the array is 2 MB and the same walk mostly hits L2/L3; at 2048 it is 32 MB, larger
## than L3, so every read goes to DRAM. The hotspot moved because the data outgrew the cache.

== B4. Diagnosis ==
hotspot 1: cause = stride/cache misses because cold_column_probe walks down columns of a 32 MB row-major array
hotspot 2: cause = wasteful work (memory traffic): refresh_history makes a full pass over 32 MB per epoch
## Hint: the evidence is the self % of cold_column_probe, and its code: the inner loop walks down a column.
